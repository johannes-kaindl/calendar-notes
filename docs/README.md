# Calendar and Contact Notes — documentation

Organised after [Diátaxis](https://diataxis.fr/): learning something and fixing something are different needs, so they live on different pages. Only the kinds that have content are listed here.

**New here?** → [Getting started](getting-started.md) — from the install to your first mirrored event note.

**Something not working?** → [Troubleshooting](troubleshooting.md) — the exact message you see, what it means, what to do.

| | |
|---|---|
| **[Getting started](getting-started.md)** | Learning-oriented. Add an account, find your calendars, preview and run the first sync. |
| **[Troubleshooting](troubleshooting.md)** | Task-oriented. "Connection test failed", "No collections are enabled yet", "This note is not a mirrored event or contact", conflicts and hand edits. |
| **[Plugin API](API.md)** | Information-oriented, for plugin authors (in German). Read events and contacts, commands as tool definitions, plan and execute, mail transports. |
| **[Dependency audit](AUDIT.md)** | Explanation-oriented. Which `npm audit` advisories apply to this plugin and why they do not affect a vault. |

The [README](https://github.com/johannes-kaindl/calendar-notes/blob/main/README.md) covers what the plugin does, adoption of existing notes, every command and setting, and the limits.

---

`SMOKE.md` and `smoke/` hold the maintainer's smoke-test checklist and measurements; they are not user documentation. Specs, plans, release notes and server findings live outside the repository.
